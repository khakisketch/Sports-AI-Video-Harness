# 대화로 제작을 진행하는 방법

## 시작과 수정

사용자는 Codex 또는 Claude Code에서 내려받은 프로젝트 폴더를 열고 원하는 결과를 말한다. 처음에는 “우리 회사의 초보자용 운동 영상을 기획해 줘. 새 유료 생성은 하지 마” 정도로 시작해도 된다. AI 감독은 회사·대상·목적·기존 자료를 확인하고, 판단에 꼭 필요한 질문만 한다. 이미 정한 사항은 다시 묻지 않는다.

주제 추천이면 이유가 다른 두세 가지 안을 제시한다. 제작·편집 요청이면 해당 단계부터 진행한다. “자막을 더 크게”라는 수정에 주제를 다시 고르거나 새 동작 영상을 만들지 않는다. 회사·강사·목소리·촬영 톤과 사용권을 정한 뒤 시리즈 기준으로 남겨 다음 편에서도 재사용한다.

## 실제 제작 흐름

| 단계 | 사용자가 하는 일 | 시스템이 준비하는 것 |
|---|---|---|
| 요청 | 목적·대상·원하는 결과를 말함 | 현재 자료·진행 상태·미확정 사항 정리 |
| 기획 | 제안 중 선택하거나 수정 | 대본, 장면의 이유, 보여줄 동작과 소리의 연결 |
| 미리보기 | 실제 시간으로 보고 의견 전달 | 기존 자료·도식·필요한 3D 블로킹을 조합한 시안 |
| 새 제작 확인 | 입력·견적·횟수·한도 확인 | 필요한 컷만 외부 모델 호출 준비, 중복 검사 |
| 컷 검토 | 인물·동작·설명 확인 | 실제 결과 확인과 채택 여부, 문제 구간 기록 |
| 편집 | 문구·속도·화면 수정 요청 | 채택 원본을 유지하고 자막·도식·음량·전환 편집 |
| 최종 확인 | 콘텐츠·운동 검토 및 인수 | 영상, 편집 소스, 사용 자료와 확인 기록 정리 |

감독은 조사·대본, 시각 연출, 독립 검토 역할을 필요한 때 호출한다. 역할 설정을 설치한 것과 실제 호출한 것은 구분한다. 독립 검토에는 감독의 점수 대신 확정 요청·기준·실제 결과를 전달한다. 파일 검사만으로 자연스러움이나 운동 정확성을 승인하지 않는다.

## 기획과 편집의 판단 기준

시청자가 무엇을 이해하고 따라 할지 먼저 정한다. 각 장면은 새 정보·행동·설명할 필요가 있어야 한다. 구도와 카메라는 필요한 전신·지지점·주시점을 보여주기 위해 선택한다. 정지 사진의 확대나 많은 컷으로 실제 동작 검토를 대신하지 않는다. 운동 시범의 첫 준비→수행→복귀는 끊김 없이 볼 수 있도록 한다.

기존 원본과 별도 자막·도식을 조합하고 작은 수정에는 관련 부분만 다시 출력한다. 음성을 확정한 뒤 실제 발화와 동작 큐에 시간을 맞춘다. 음성 활동 분석은 말소리가 있는 구간을 찾는 기능이며, 단어별 정렬이나 직접 청취를 했다는 뜻이 아니다. 원본에서 잘린 신체는 확대·크롭으로 복구됐다고 하지 않는다. 내부 검토 상태를 시청자 화면에 임의로 올리지 않는다.

## 원본과 작업 상태

계획, 검토, 실행 이력을 기준으로 장면마다 원본·버전·의존 관계·채택 상태를 연결한다. 자막 수정은 편집만, 인물·동작 결함은 해당 컷만, 교육 내용 변경은 해당 대본과 연결 장면을 수정한다. 미확인 컷은 내부 확인용으로만 사용하며 본편 채택으로 바꾸지 않는다. 정확한 동작은 전문가가 확인한 기준 원본을 우선한다.

현재의 Blender 예시는 좌표와 관절 연결·접촉·구도를 검토하는 마네킹이다. 인체 운동의 안전성이나 전문가 승인을 입증하지 않는다. 근거가 필요한 운동 설명은 출처와 확인 범위를 남긴다. AI 검토자는 운동 전문가나 실제 인수 담당자의 서명을 대신하지 않는다.

## 외부 도구와 실행 권한

생성 모델은 외부 호스팅 API로 실행한다. 로컬 GPU나 모델 가중치 설치는 필수 조건이 아니다. 영상·음성·이미지·립싱크·보이스 복제의 공통 작업 종류 중 실행 연결이 있는 것은 LTX 영상과 OpenAI 문자 과금 음성이다. 나머지는 정의 또는 후보 단계다. 전문 플랫폼은 실제 장점과 연결된 기능이 있을 때 선택한다.

공식 API는 장면·공급자별 통화와 한도를 확인한다. 현재 가격과 실제 청구는 구분하고 미확인 청구를 0으로 바꾸지 않는다. 계획 검사기는 에이전트가 따라야 할 점검이며, 호스트의 모든 외부 도구 호출을 차단하는 보안 장치는 아니다. 새 유료 실행에는 현재 대본·장면·자산·도구·한도·횟수·재시도 범위를 확인한다.

중단된 작업은 저장한 ID로 조회하고 결과를 회수한다. 접수 여부가 불확실한 작업을 자동 재제출하지 않는다. 서명된 다운로드 주소는 장기 기록에 저장하지 않는다. 설치·계정 키 등록·연결 코드 존재·실제 생성 성공·최종 품질 통과를 각각 구분한다.

## 설치 담당자 참고

기준 설정은 config/에, 공유 역할은 agents/에 있다. 설치 점검은 `python3 scripts/bootstrap.py --check`, 역할 정의 확인은 `python3 scripts/setup_studio_agents.py --check`, 전체 오프라인 검사는 `python3 -m unittest discover -s tests`로 수행한다. 현재 요청 연결은 `python3 scripts/factory.py prepare --request "원하는 작업"`으로 점검할 수 있다. 패킷 생성은 실제 외부 실행이 아니다.

새 계획은 `python3 scripts/production.py init --episode EP001 --version plan-v1`으로 시작한다. 기준 필드는 templates/production/과 각 실행기의 `--help`를 따른다. 생성 직전에는 해당 계획에 `scripts/production.py check ... --stage generate`를 실행한다. 사용자는 이 명령을 외울 필요가 없으며 에이전트가 실제 상태와 현재 권한을 확인해 실행한다.

검사와 로컬 편집은 반복할 수 있지만 공개판에는 실제 고객 미디어·음성·키·승인 이력이 없다. 새 계정의 유료 호출, 독립 영상 검토, 운동 전문가 확인과 고객 인수는 설치 후 실제 작업에서 별도로 수행해야 한다.
