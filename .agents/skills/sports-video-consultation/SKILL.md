# 대화형 영상 제작 운영

지금 프로젝트에서 지시하는 사람이 사용자다. 소유자·팀원·다른 운영자·실제 고객 누구든 직접 사용할 수 있다. 영상 의뢰인, 시청자, 전문가와 사용자를 자동으로 같은 사람으로 취급하지 않는다. 한 사람이 여러 역할을 맡거나 별도 의뢰인이 없을 수도 있다. [운영 안내](../../../docs/대화형-제작운영.md)를 따른다.

기존 호출과 기록을 유지하려고 스킬 ID sports-video-consultation은 보존했다. 기능은 대화로 영상 작업 전체를 이어가는 운영 지침이다. 실제 미디어 생성·전문 편집은 해당 도구와 스킬을 사용한다.

## 현재 요청에서 시작하기

- AGENTS.md, README.md, config/series.json, config/production-policy.json과 해당 편의 실제 기록에서 현재 단계·결과·결정·권한·남은 문제를 이어받는다. 수정 시각이나 요약만으로 최신 승인·완료를 정하지 않는다.
- 이번에 원하는 결과를 판단한다. 추천·기획·미리보기뿐 아니라 자산 준비, 견적, 실제 생성, 편집, 검수, 수정, 출력, 재개와 환경 개선도 정상적인 요청이다. 구체적 작업이 있으면 해당 단계부터 수행한다. 상태 질문에는 먼저 답하고 환경 질문을 새 영상 제작으로 바꾸지 않는다.
- 필요한 단계만 연결해 요청한 결과까지 진행한다. 제작 요청을 기획 문서 작성으로 끝내거나 자막 수정 요청에 새 주제 선정부터 요구하지 않는다. 이번 요청의 완료 기준과 다음에 검토할 결과를 구체적으로 둔다.

## 제작 팩토리로 역할·도구 준비

- 요청 단계와 역할·도구 경로를 정할 때 `python3 scripts/factory.py prepare --request "사용자의 요청"`을 내부 라우팅으로 사용한다. 특정 단계가 명확하면 `--stage`를 지정하고 현재 편은 series 설정에서 이어받는다.
- 환경 준비·설정 변경을 요청받았거나 도구 상태에 불확실성이 있으면 `python3 scripts/factory.py audit`로 로컬 도구, 역할 커버리지, 프로젝트 스킬 해시와 필수 파일을 확인한다.
- `prepare`는 역할별 작업 지침 패킷이지 작업 자체의 완료가 아니다. 해당 단계의 실제 작업을 계속 수행하고, 필요한 산출물·시각 증거·검수·기록을 만들며, 기존 도구 스크립트로 검증한다.
- Higgsfield·HeyGen은 설정된 도구 라우트를 따르되 로컬 CLI에서 연결·계정·견적을 안다고 가정하지 않는다. 필요한 대화에서 현재 읽기/견적 도구를 조회한다. 이 팩토리는 외부 호출, 생성, 업로드, 결제, 게시를 실행하지 않는다.

## 감독과 전문 에이전트의 제작 사고 순서

기본은 현재 대화의 총괄 감독이 필요한 조사·대본과 시각 설계를 전문 하위 에이전트에 위임하고, 실제 렌더의 독립 검수는 별도 맥락에서 수행하는 것이다. [전문 제작 운영](../../../docs/전문제작-운영.md)과 config/studio-agents.json을 따른다. 작은 수정은 관련 역할만 수행하고, 역할 이름이나 파일 존재를 실제 호출로 기록하지 않는다. 사용자가 새 기획을 요청하면 프로듀서가 기존 상태·목표·범위를 읽고, 콘텐츠 검토자가 근거와 미확정을 나누며, 기획자와 연출자·편집자가 대사·시범·카메라·도식·소리·전환을 화면별로 구성한다. 그 뒤 회의적 시청자 관점에서 갑작스러운 진입, 반복, 주시점 혼란, 말과 화면의 불일치를 찾고, QA가 실제 결과·기술·납품 상태를 분리해 정리한다.

이 순서는 모든 요청에 풀코스로 적용하지 않는다. 자막 수정은 자막·싱크·레이아웃과 영향받는 QA만 수행한다. 영상 생성은 생성 전 계획·견적·실행 권한을 확인하고, 생성 완료 뒤 실제 결과를 편집·검토한다. 설치·환경 정리는 새 미디어를 만들지 않는다. 역할 이름을 독립 AI/전문가의 검토처럼 표현하지 않는다.

열린 기획 요청은 알려진 조건으로 성격이 다른 2–3안을 제안하고 추천 이유를 설명한다. 사용자가 특정 자세·결과·편집을 정했으면 그 단계부터 시작한다. 모호성은 완성물의 방향이나 비용·안전에 영향을 줄 때만 좁혀 묻고, 나머지는 명시한 합리적 가정으로 계속 진행한다.

## 요청에 맞는 도구로 연결하기

사용자는 결과를 지시하며 에이전트는 편집자 역할까지 수행한다. 장면마다 새 AI 생성의 필요성을 판단하고 기존 영상·사진·제목/단색 화면·도식·자막·소리를 조합한다. 단순 문구·트림·강조·일반 전환은 현재 도구로 해결 가능한지 먼저 보고, 허용된 편집은 매 단계 확인을 요구하지 않고 완성·검수까지 이어간다. ‘제목 화면을 넣어 줘’에 인물 생성·새 운동 기획·유료 모델을 강제하지 않는다. 구체적 비용·자산 사용·외부 실행 권한은 현재 범위대로 적용한다.

| 요청 | 적용할 기존 흐름 |
|---|---|
| 추천·막연한 기획 | 다른 성격의 2–3안과 추천 이유·첫 화면·기존 자료 활용을 제안. 구체적 요청에는 후보 선정을 강제하지 않음 |
| 대본·장면·인물·동작 설계 | 제작운영과 필요한 NolanX 스킬. 말·행동·구도·전환·참조 역할을 계획에 연결 |
| 자산·강사·음성 준비 | 채택 기록·원본·서비스 호환 확인. 후보 확인과 실제 생성·등록·학습을 구분 |
| 프리비주얼 | 필요한 Blender 또는 HyperFrames 스킬·로컬 실행기. 실제 결과와 표현 한계 검토 |
| 도구 선택·견적 | 현재 입력·단위·부작용과 서비스별 비용·재사용/생성 범위 확인 |
| 실제 생성 | 현재 요청·충분한 기존 권한·품질/실행 점검을 적용하고 선택한 서비스의 스킬·도구로 수행. 작업 ID·결과·실소모 기록 |
| 편집·자막·음량·출력 | 요청에 맞는 로컬 도구나 공식 편집 스킬. 새 생성이 필요 없는 수정은 기존 자산으로 진행 |
| 검수·불만·수정 | 생성 전 preproduction-review, 생성 후 실제 영상·음성·기술/내용 검토. 영향받는 부분만 수정·재검수 |
| 결과 정리·재개 | 실제 파일·판정·미확인·남은 작업과 연결 버전을 정리. 발송·게시 요청은 별도로 판단 |

표는 단계별 새 승인이나 필수 풀코스를 뜻하지 않는다. 현재 요청과 기존 권한이 충분하면 끝까지 이어간다. 도구 고유 절차는 해당 스킬을 읽는다. 새 자율 에이전트 서버나 플랫폼 복제 엔진을 추가하지 않는다.

구체적인 편집 요청은 [편집 완성 기준](../../../docs/편집완성-운영.md)을 함께 적용한다. 대사·실제 발화·동작 큐·자막 구간과 카메라 재구도·전환 목적은 EDL에서 연결하고, 화면 속 발화를 옮긴 경우 voice-over와 립싱크 상태를 분명히 쓴다. 원본의 손발 잘림과 출력 크롭을 먼저 구별하며 원본 밖 픽셀을 복구한 것처럼 표현하지 않는다. 카메라 이동은 주시점을 바꿀 이유가 있을 때 사용하고, 첫 한 주기·접촉점·해상도·안전 여백을 실제 화면으로 재검수한다. 자연스러운 한국어 문장형 자막과 제한된 강조를 우선한다. 외부 편집/자막 스킬은 필요한 기능이 있을 때만 읽어 적용하고 스타일 기본값이나 원격 업로드 절차를 그대로 상속하지 않는다.

## 대화와 결정 관리

- 사용자가 모델·fps·JSON을 모두 채우게 하지 않는다. 알고 있는 조건으로 제안·준비하고 중요한 질문만 보통 한 개, 필요할 때 최대 세 개로 묶는다. 답이 필요한 작업과 독립적인 준비를 구분한다.
- 사실·사용자 선택·AI 제안·가정·미확정을 구별한다. 취향은 사용자/작업 공간·의뢰인/브랜드·시리즈·편·장면 범위와 발언 근거를 남긴다. 작업자가 바뀌었다고 기존 시리즈 자산을 폐기하지 않고 브랜드가 바뀌었는데 이전 의뢰인 자료를 자동 상속하지도 않는다.
- [작업 기록 양식](../../../templates/consultation/brief.md)은 필요할 때 사용한다. 기존 consultation.md도 결정 이력으로 계속 읽는다. 실제 입력은 plan.json, 검토·실행 승인은 reviews.json, 결과는 jobs.json을 기준으로 연결한다. 기록 작성이 승인이나 실행을 뜻하지 않는다.
- 별도 의뢰인이나 승인 담당이 지정되지 않았다면 가상의 고객 승인 단계를 만들지 않는다. 사용자가 담당하는 선택·실행 결정과 실제 지정된 의뢰인 검토·운동 전문가 확인을 구분한다. 역할 표기는 계정 인증이나 다중 사용자 권한 시스템이 아니다.
- “좋아/진행해”는 바로 앞의 구체적 안과 실제 권한에 연결한다. 충분한 승인은 재사용하되 한 편의 음성 시험·예산을 다음 편으로 확장하지 않는다. 현재 유료 생성 금지 같은 제한은 명시적으로 변경되기 전까지 유지한다.
- “부자연스럽다/재미없다”는 실제 화면·대본·시간에서 원인을 좁힌다. 못 본 원인은 가설로 남기고 변경할 부분·유지할 부분·비용/검토 영향을 제시한다. 비용 드는 재생성부터 하지 않는다.

## 품질과 전달

[도구 역할 기준](../../../docs/도구역할-선택기준.md)에 따라 채택 자산과 검증한 경로를 우선하고 품질·일관성·총비용으로 도구를 선택한다. 정지 시안·기술 검사·전사 일치를 실제 연기·동작·음성 품질로 전용하지 않는다. 스킬이나 파일의 존재만으로 통과시키지 않는다.

새 영상 기획에는 [화면·행동 설계](../../../docs/영상연출-설계기준.md)와 [역할별 연출 검토](../../../docs/연출검토.md)의 회의적 시청자 패스를 적용한다. 대사와 텍스트만 바뀌는 정지 인물 템플릿에 주제를 끼워 넣지 않는다. 시청자가 보게 될 행동·비교·발견과 시간별 전개를 제안하고 필요한 Blender 블로킹·HyperFrames 편집·외부 전문 기능으로 이어간다. 자막 교정 등 특정 요청을 받았을 때 새 연출 기획을 강제하지 않는다.

새 기획의 검토본은 짧은 연출 의도와 ‘처음 무엇을 보고 → 무엇을 발견하며 → 무엇을 이해하고 끝나는가’를 먼저 읽게 한다. 기존 plan.json의 direction·shots·transitions를 사용하며 독립된 승인 문서를 늘리지 않는다. `production.py packet`이 이 흐름을 먼저 출력하고 세부 시간표를 뒤에 붙인다. 화면·조명 의도는 프로젝트의 director-visual-language, 컷 방향·행동 연결은 continuity-editing-axis-match를 필요한 때 적용한다. 매초 표·얼굴 오프닝·특정 컷 수는 필수 형식이 아니다. 설치나 환경 개선 요청에는 새 에피소드·새 미디어를 만들지 않는다.

사용자에게는 이번 결과와 선택 이유, 확인한 품질, 남은 문제, 다음 작업을 설명한다. 실제 의뢰인 검토용·시청자용 문구와 작업자에게 설명할 운영 내용을 구별한다. 기술 세부 사항은 판단에 필요한 만큼 제시한다.

기대 행동은 [점검 사례](../../../docs/고객대화-점검사례.md)로 확인한다. 예시·형식 검사를 실제 사용자 대화나 독립 행동 평가의 통과로 표현하지 않는다.
